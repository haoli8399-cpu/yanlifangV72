## 1. 一级导航体系

演立方 V4.7 按 **角色 + 场景** 划分为 7 大端口，每个端口拥有独立的导航体系和路由空间。端口之间通过数据流（线索 → 商机 → 方案 → 报价）和跳转链接（如客户方案 H5 → Agent 端）连接。

### 1.2 端口概览

| 端口 | 路由前缀 | 页面数 | 导航模式 | 目标用户 | 核心场景 |
|------|---------|--------|---------|---------|---------|
| 首页 | `/` | 1 | 无导航（Landing） | 公众 | 品牌展示 + 工具入口 + 角色分发 |
| Agent 端 | `/agent` | 7 | 顶部水平导航 | 企业活动决策人 | AI 方案生成 + 方案管理 + 消息 |
| Supplier 端 | `/supplier` | 14 | 顶部水平导航 | 活动公司销售 | 线索跟进 + 商机管理 + 方案报价 |
| Admin 端 | `/admin` | 16 | 左侧垂直侧边栏 | 平台运营 | 平台管理 + 数据监控 + 系统配置 |
| m 端 | `/m` | 6 | 底部 Tab 栏 | C 端消费者 | 浏览方案 + 提需求 + 消息 |
| 增长工具 H5 | `/tools` | 3 | 无导航（漏斗） | 公众 | 工具获客 → 留资 |
| 客户方案 H5 | `/p` | 1 | 无导航（单页） | 企业决策人 | 方案预览 + 确认 |

### 1.3 路由设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 端口隔离 | 每个端口使用独立路由前缀，权限边界清晰 | `/agent/*` 仅企业决策人可访问 |
| 语义化路径 | 路径名使用业务语义英文，可读性强 | `/agent/solutions` 而非 `/agent/p2` |
| 动态参数 | 详情页使用 `$id` 参数，遵循 TanStack Router 约定 | `/agent/quotations/$id` |
| 角色映射 | 路由前缀直接映射用户角色，无需额外权限判断 | `/supplier/*` → 销售角色 |

### 3.2 数据流节点说明

| 步骤 | 源页面 | 目标页面 | 传递数据 | 触发方式 |
|------|--------|---------|---------|---------|
| ① | 增长工具 H5 | LeadCaptureModal | 工具问答结果 + 用户输入的需求摘要 | 用户点击结果页 CTA |
| ② | LeadCaptureModal | 线索中心（Supplier） | 留资信息（姓名 / 电话 / 公司 / 需求） | 留资表单提交 |
| ③ | LeadCaptureModal | 线索详情 | 留资完整数据 + LeadScoreBadge 评分 | 自动创建线索记录 |
| ④ | 线索详情 | 商机中心 | 线索转化后的商机数据 | 销售点击"创建商机" |
| ⑤ | AI 顾问（Agent） | AI 对话 | 用户自然语言需求 → AI 提取关键信息 | 用户输入需求并提交 |
| ⑥ | AI 对话 | 我的方案 | AI 生成的方案推荐 + 匹配的供应商方案 | AI 分析完成 |
| ⑦ | 我的方案 | 方案管理（Supplier） | 方案需求关联到对应商机/供应商 | 方案推荐匹配 |
| ⑧ | 商机中心 | 方案管理 | 商机详情 → 生成方案 | 销售点击"生成方案" |
| ⑨ | 方案管理 | 客户方案 H5 | 方案完整数据（/p/$proposalId） | 销售点击"发送给客户" |
| ⑩ | 客户方案 H5 | 方案管理 | 客户确认 / 修改反馈 | 客户在 H5 页操作 |
| ⑪ | 方案管理 | 报价管理 | 方案 → 报价转换 | 销售点击"生成报价" |
| ⑫ | 报价管理 | 消息中心（Agent） | 报价通知 + 报价 ID | 销售点击"发送报价" |

## 6. 信息层级原则

### 6.1 三级信息层级模型

演立方 V4.7 采用 **三级信息层级模型**，每个页面应明确区分三个信息层级：

```
┌─────────────────────────────────────────────────────┐
│  Level 1: 主焦点（Primary Focus）                    │
│  ─────────────────────────────────                   │
│  定义：用户进入页面后首先需要关注和操作的核心信息        │
│  视觉：最大字号 / 最强色彩对比 / 最显眼位置             │
│  占比：页面视觉权重的 50%-60%                          │
│  字号：Display（36/30/24px）或 Heading-LG（22px）     │
│  色彩：var(--yl-primary) 或 var(--yl-text-primary)    │
│                                                     │
│  ┌─────────────────────────────────────────────┐    │
│  │  Level 2: 次级信息（Secondary Information）   │    │
│  │  ─────────────────────────────────            │    │
│  │  定义：辅助主焦点的上下文信息和支持操作          │    │
│  │  视觉：中等字号 / 中等对比 / 次要位置           │    │
│  │  占比：页面视觉权重的 25%-35%                   │    │
│  │  字号：Heading（18/16/14px）或 Body-LG（16px）  │    │
│  │  色彩：var(--yl-text-secondary)                │    │
│  │                                               │    │
│  │  ┌───────────────────────────────────────┐   │    │
│  │  │  Level 3: 辅助信息（Auxiliary Info）    │   │    │
│  │  │  ─────────────────────────────          │   │    │
│  │  │  定义：补充说明、时间戳、状态标签等       │   │    │
│  │  │  视觉：最小字号 / 低对比 / 边缘位置       │   │    │
│  │  │  占比：页面视觉权重的 10%-15%             │   │    │
│  │  │  字号：Body（14/13px）或 Caption（12px）  │   │    │
│  │  │  色彩：var(--yl-text-tertiary)           │   │    │
│  │  └───────────────────────────────────────┘   │    │
│  └─────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

### 6.2 层级设计 Token 映射

| 层级 | 用途 | 字号 Token | 颜色 Token | 字重 | 示例 |
|------|------|-----------|-----------|------|------|
| L1 主焦点 | 页面标题 / 核心 CTA / 关键数据 | Display / Heading-LG | --yl-text-primary / --yl-primary | 600-700 | "AI 活动顾问"、KPI 数值 |
| L2 次级信息 | 卡片标题 / 表单标签 / 操作按钮 | Heading-MD / Body-LG | --yl-text-secondary | 500-600 | "推荐方案"、筛选条件 |
| L3 辅助信息 | 时间戳 / 状态标签 / 说明文字 | Body-SM / Caption | --yl-text-tertiary | 400 | "2 小时前"、StatusTag |

### 6.3 各页面类型的层级应用

#### 6.3.1 AI 交互型页面（Agent 首页 / AI 对话）

```
L1 主焦点：AI 输入框 + 提交按钮
  ├─ 占据 Hero 区域，大面积输入框 + 醒目 CTA
  └─ 视觉权重 50%

L2 次级信息：场景芯片 / 需求提取面板 / 推荐方案卡片
  ├─ 围绕主焦点提供上下文和辅助操作
  └─ 视觉权重 35%

L3 辅助信息：最近方案卡片 / 热门推荐
  ├─ 底部区域，低视觉权重
  └─ 视觉权重 15%
```

#### 6.3.2 列表管理型页面（方案发现 / 商机中心 / 线索中心）

```
L1 主焦点：列表结果区域（卡片网格 / 表格）
  ├─ 占据页面主体区域
  └─ 视觉权重 55%

L2 次级信息：筛选/搜索条件区
  ├─ 顶部或侧边，提供结果控制
  └─ 视觉权重 30%

L3 辅助信息：结果计数 / 排序选项 / 分页
  ├─ 列表上下边缘，低视觉权重
  └─ 视觉权重 15%
```

#### 6.3.3 工作台型页面（销售作战台 / 跟进中心）

```
L1 主焦点：当前操作对象（商机详情 / 跟进时间线）
  ├─ 中列区域，用户当前关注的核心
  └─ 视觉权重 45%

L2 次级信息：上下文列表（商机列表 / 客户信息）
  ├─ 左列和右列，提供选择和辅助
  └─ 视觉权重 35%

L3 辅助信息：KPI 统计 / AI 建议 / 操作记录
  ├─ 顶部和底部，低视觉权重
  └─ 视觉权重 20%
```

#### 6.3.4 漏斗型页面（增长工具 H5 / 客户方案 H5）

```
L1 主焦点：当前问题 / 核心结论
  ├─ 居中大字，占据屏幕主体
  └─ 视觉权重 65%

L2 次级信息：选项 / 推荐方案 / 费用拆解
  ├─ 紧跟主焦点，提供选择和详情
  └─ 视觉权重 25%

L3 辅助信息：进度指示 / 说明文字 / CTA
  ├─ 底部固定区域
  └─ 视觉权重 10%
```

#### 6.3.5 管理后台型页面（Admin 端各页）

```
L1 主焦点：数据表格 / 核心指标
  ├─ 页面主体区域
  └─ 视觉权重 55%

L2 次级信息：筛选条件 / 操作按钮
  ├─ 表格上方工具栏
  └─ 视觉权重 30%

L3 辅助信息：分页 / 表格行内状态标签
  ├─ 表格上下边缘
  └─ 视觉权重 15%
```

### 6.4 信息层级设计检查清单

| 检查项 | 标准 | 验证方法 |
|--------|------|---------|
| 主焦点唯一性 | 每个页面只有 1 个主焦点区域 | 眯眼测试：模糊看页面，最先注意到的是否是主焦点 |
| 层级对比度 | L1/L2/L3 之间有明确视觉差异 | 字号差 ≥ 4px，颜色差 ≥ 1 个层级 |
| 信息密度 | L1 不超过页面 60%，L3 不低于 10% | 计算各层级区域面积占比 |
| 视觉流向 | 用户视线应从 L1 → L2 → L3 自然流动 | F 型或 Z 型视线追踪 |
| 层级一致性 | 同类型页面使用相同的层级分配 | 跨页面对比检查 |

## 7. IA 优化建议

### 7.1 Supplier 端导航分组优化

**问题**：Supplier 端 14 个页面中 8+ 项平铺在顶部导航，超出顶部导航的舒适承载量（推荐 ≤ 5 项主项）。

**建议**：按业务域分为 4 组下拉菜单。

```
优化前（8 项平铺）：
[作战台] [跟进中心] [商机中心] [线索中心] [方案管理] [报价管理] [艺人管理] [AI反馈]

优化后（4 组下拉）：
[工作台 ▾]  [商机管理 ▾]  [内容管理 ▾]  [系统 ▾]
  ├─作战台      ├─商机中心      ├─方案管理      └─AI反馈
  └─跟进中心    └─线索中心      ├─报价管理
                               └─艺人管理
```

| 分组 | 页面 | 分组逻辑 | 使用频率 |
|------|------|---------|---------|
| 工作台 | 作战台、跟进中心 | 日常高频操作入口 | 每日多次 |
| 商机管理 | 商机中心、线索中心 | 销售漏斗管理 | 每日数次 |
| 内容管理 | 方案管理、报价管理、艺人管理 | 交付物管理 | 每日数次 |
| 系统 | AI 反馈 | 系统辅助功能 | 每周数次 |

**预期效果**：顶部导航项从 8 个减少为 4 个，降低 50% 认知负荷。

### 7.2 Agent 端 AI 输入全局化

**问题**：Agent 端 AI 输入框仅出现在首页（/agent），其他页面（方案发现、我的方案等）缺少快速发起 AI 咨询的入口。

**建议**：在 Agent 端所有页面的顶部导航栏或全局浮动按钮中提供 AI 输入入口。

```
方案 A：导航栏内嵌输入框
┌─────────────────────────────────────────────────────────────┐
│ [Logo] AI顾问 方案发现 AI对话 我的方案 消息  [🔍 问AI...] 🔔 👤│
│                                            └─ 品牌色边框输入框  │
└─────────────────────────────────────────────────────────────┘

方案 B：全局浮动按钮
┌─────────────────────────────────────────────────────────────┐
│ [Logo] AI活动顾问  方案发现  AI对话  我的方案  消息中心  🔔 👤 │
│                                                             │
│                    页面内容                                  │
│                                                             │
│                                                  ┌────────┐ │
│                                                  │  AI ✨ │ │
│                                                  └────────┘ │
└─────────────────────────────────────────────────────────────┘
```

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| A 导航栏内嵌 | 入口稳定，不遮挡内容 | 占用导航栏空间 | 推荐 |
| B 浮动按钮 | 不占用导航栏空间，有动效 | 可能遮挡内容 | 备选 |

**预期效果**：用户在任何 Agent 端页面都能一键发起 AI 咨询，缩短操作路径。

### 7.3 m 端"提需求"按钮强化

**问题**：m 端底部 Tab 的"提需求"与其他 Tab 视觉权重相同，未能突出其作为核心转化入口的地位。

**建议**：将"提需求"设计为凸起按钮（FAB 风格），品牌色背景 + 向上偏移。

```
当前设计：
┌──────────────────────────────┐
│  🏠    🔍    ✏️    💬    👤  │
│ 首页  找方案  提需求  消息  我的│
└──────────────────────────────┘
    （5 项视觉权重相同）

建议设计：
┌──────────────────────────────┐
│                              │
│  🏠    🔍         💬    👤  │
│ 首页  找方案      消息  我的  │
│            ╭────╮            │
│            │ ✏️ │            │
│            │提需求│            │
│            ╰────╯            │
└──────────────────────────────┘
    （"提需求"凸出，品牌色背景）
```

| 属性 | 规格说明 |
|------|---------|
| 按钮形状 | 圆形，直径 56px |
| 按钮背景 | `var(--yl-primary)` #5B4FD6 |
| 按钮图标 | 白色，24px |
| 按钮文字 | 白色，12px |
| 偏移量 | 向上偏移 8px（超出 Tab 栏） |
| 阴影 | `var(--yl-shadow-md)` |

**预期效果**：核心转化入口视觉权重提升 200%，点击率预计提升 30-50%。

### 7.4 跨端跳转过渡设计

**问题**：跨端跳转（如客户方案 H5 → Agent 端、首页 → 各端登录页）缺少统一的过渡设计，用户在跳转时可能产生"离开应用"的割裂感。

**建议**：建立跨端跳转过渡规范。

| 跳转场景 | 过渡方式 | 实现 |
|---------|---------|------|
| 首页 → Agent/Supplier/Admin 端 | 品牌色全屏过渡 + Loading | CSS animation 200ms |
| 客户方案 H5 → Agent 端 | 顶部提示条"在电脑端查看更多" | Toast + 跳转链接 |
| 增长工具 H5 → 留资成功 | 品牌色全屏过渡 + 成功动画 | Success animation 500ms |
| Agent 端 → 客户方案 H5 | 新窗口打开 + 品牌色边框 | `target="_blank"` |

### 7.5 销售作战台信息层级重组

**问题**：销售作战台当前 4 个区域平铺，信息层级混乱，主焦点不明确。

**建议**：按三级信息层级模型重组。

```
重组前（4 区域平铺）：
┌───────────────────────────────────────┐
│ KPI1  KPI2  KPI3  KPI4                │ ← L3（但当前占了 L1 的位置）
├─────────┬──────────────┬──────────────┤
│ 商机列表 │ 客户详情      │ AI 方案      │ ← L1+L2 混合
│         │ 5+ 区块纵向堆叠│              │
├─────────┴──────────────┴──────────────┤
│ [跟进时间线] [AI话术] [行动]            │ ← L2（但位置像 L3）
└───────────────────────────────────────┘

重组后（三级层级清晰）：
┌───────────────────────────────────────┐
│ KPI1  KPI2  KPI3  KPI4                │ ← L3 辅助：压缩为可折叠条
├─────────┬──────────────┬──────────────┤
│ L2 列表  │ L1 主焦点    │ L2 辅助      │
│         │              │              │
│ 商机列表 │ ┌──────────┐ │ AI 方案卡片  │
│ (选择)  │ │需求理解   │ │ (推荐)      │
│         │ │──────────│ │              │
│         │ │AI 分析   │ │              │
│         │ │──────────│ │              │
│         │ │状态跟踪   │ │              │
│         │ └──────────┘ │              │
│         │              │              │
│         │ [跟进▼ 抽屉]  │              │ ← L2：移入抽屉
└─────────┴──────────────┴──────────────┘
```

| 区域 | 层级 | 优化措施 |
|------|------|---------|
| KPI 统计 | L3 辅助 | 压缩为可折叠横条，默认展开，可手动收起 |
| 商机列表 | L2 次级 | 保持左列，宽度可调 |
| 客户详情 | L1 主焦点 | 中列，3 个分组用分隔线划分（需求理解 / AI 分析 / 状态跟踪） |
| AI 方案 | L2 次级 | 右列，保持不变 |
| 底部 Segmented | L2 次级 | 移入中列底部抽屉，点击展开 |

### 7.6 跟进中心区域精简

**问题**：跟进中心 4 个区域（提醒 + 统计 + 列表 + 详情）信息过载。

**建议**：合并统计卡片到提醒区域，减少区域数量。

```
优化前（4 区域）：
┌───────────────────────────────────────┐
│ [提醒卡片1] [提醒卡片2] [提醒卡片3]     │ ← 区域 1
├───────────────────────────────────────┤
│ [统计1] [统计2] [统计3] [统计4]        │ ← 区域 2
├───────────┬───────────────────────────┤
│ 商机分组   │ 跟进详情                   │ ← 区域 3+4
│ 列表       │ 时间线 + AI话术 + 输入     │
└───────────┴───────────────────────────┘

优化后（3 区域）：
┌───────────────────────────────────────┐
│ [提醒+统计合并卡片]                     │ ← 区域 1（合并）
│  紧急跟进: 5  今日待办: 12  本周完成: 8  │
├───────────┬───────────────────────────┤
│ 商机分组   │ 跟进详情                   │ ← 区域 2+3
│ 列表       │ 时间线 + AI话术 + 输入     │
└───────────┴───────────────────────────┘
```
