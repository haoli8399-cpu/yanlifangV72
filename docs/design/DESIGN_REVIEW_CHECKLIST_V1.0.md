## 一、PRD 对齐度审查

| # | 检查项 | 通过标准 |
|:---:|:---|:---|
| 1.1 | 用户角色覆盖 | 四类用户角色（企业客户/销售/运营/C端）在设计方案中均有体现 |

## 二、UX 体验质量审查

| # | 检查项 | 通过标准 |
|:---:|:---|:---|
| 2.1 | 信息架构 | 导航层级合理、页面入口明确、无深层嵌套（≤3 级） |
| 2.2 | 用户流程 | 每条流程有明确入口→操作→反馈→结果，无死胡同 |
| 2.3 | 主次分明 | 每个页面 3 秒内可识别主视觉焦点和主操作 |
| 2.4 | 认知负荷 | 单屏同时展示的关键信息 ≤ 7 个，无信息堆砌 |
| 2.5 | 引导清晰 | 新用户不迷茫，每个页面有明确的下一步行动指引 |
| 2.6 | 用户画像匹配 | 设计方案符合四类用户的使用习惯和操作频率 |
| 2.7 | 情感体验 | 方案页有专业可信感、销售端有效率感、客户端有被重视感 |

## 三、Design System 一致性审查

| # | 检查项 | 通过标准 |
|:---:|:---|:---|
| 3.1 | 品牌色 | 全文统一 #5B4FD6，未出现旧色 #6E59F5 / #7c3aed |
| 3.2 | Color Token | 定义了完整的语义色 / 状态色 / 背景色 / 文字色 / AI 专属色 |
| 3.3 | Typography | 定义了 Display / Heading / Body / Caption / Numeric 五级，有明确的字号-字重-行高 |
| 3.4 | Spacing | 基于 4px 基准，定义了 6+ 级间距 |
| 3.5 | Radius | 定义了 4+ 级圆角，有明确的使用场景 |
| 3.6 | Shadow | 定义了 3+ 级阴影，有 AI 专属阴影 |
| 3.7 | 组件样式统一 | 所有同类组件（按钮/卡片/标签）样式一致 |
| 3.8 | 状态色彩 | 成功绿/警告橙/错误红/信息蓝 使用一致 |

## 九、可实现性审查

| # | 检查项 | 通过标准 |
|:---:|:---|:---|
| 9.1 | 技术可行性 | 设计方案在当前技术栈（React + AntD 6 + Tailwind 4）下可落地 |

## 十、否决项（一票否决）

以下任一项不通过，整个设计交付即判定为**不合格**：

| # | 否决项 | 判定标准 |
|:---:|:---|:---|
| ❌ 1 | 品牌色错误 | 出现 #6E59F5 / #7c3aed |
| ❌ 2 | 推翻现有路由 | 要求新建路由体系或重新规划 URL 结构 |
| ❌ 3 | 更换技术栈 | 要求更换 UI 组件库或前端框架 |
| ❌ 4 | 修改业务逻辑 | 要求改变状态流转/权限/报价规则 |
| ❌ 5 | 无 Design Handoff | 只有页面设计，没有可交付的开发规范 |
| ❌ 6 | 完全忽略现有代码 | 17 个已有组件一个都没有复用 |
