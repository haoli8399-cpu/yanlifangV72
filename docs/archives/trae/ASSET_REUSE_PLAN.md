## 3. 架构复用策略

### 3.1 领域驱动设计

- 三层经营对象 (Demand/TenantEngagement/ActivityProject) → 三个独立聚合根
- 四层供给语义 (Capability/ProgramModule/ServiceOffering/PlanItem) → 独立聚合根 + 版本模型
- 统一版本模型 → 所有版本化对象复用同一模式

### 3.2 权限架构

- RBAC 基础角色 → 平台治理、Tenant、客户、演员
- ABAC 动态权限 → 基于状态、有效期、授权的细粒度控制
- 行级/字段级隔离 → Tenant 数据隔离、客户数据隔离

### 3.3 状态机模式

- 统一状态转换模式 → 所有对象状态转换复用相同的审计、验证、权限检查
- 四轴正交状态 → readiness/lifecycle/publication/evidence

### 3.4 审计架构

- 统一审计事件格式 → 所有核心操作生成标准化审计记录
- 审计查询接口 → 统一的审计数据检索

## 4. 开发流程复用

### 4.1 Git 工作流

- Git Flow 变体 → feature/* 分支开发
- 小步提交 → 每次提交只包含一个逻辑变更
- 原子提交 → 提交必须通过测试

### 4.2 CI/CD

- GitHub Actions → 自动化构建、测试、部署
- 代码质量检查 → pylint/eslint、typecheck
- 测试覆盖 → 单元测试、集成测试、E2E 测试

### 4.3 测试策略

- 测试金字塔 → 单元测试 > 集成测试 > E2E 测试
- 产品不变量测试 → 30 条核心不变量的自动化验证
- 负面测试 → 越权、数据泄露、状态冲突

## 8. 复用原则

1. **能复用则复用**：优先使用成熟解决方案
2. **能演进则演进**：基于现有架构逐步扩展
3. **必须重构才重构**：只有当现有方案无法满足 PRD 要求时才重构
4. **产品事实优先**：技术实现服从 PRD 产品事实
5. **安全优先**：权限、隔离、审计必须完整实现

## 9. 风险与应对

### 9.1 技术栈风险

| 风险 | 应对 |
|:---|:---|
| FastAPI 生态成熟度 | 使用成熟第三方库，避免边缘特性 |
| Next.js 版本兼容性 | 锁定版本，定期更新 |
| PostgreSQL 性能 | 合理索引设计、查询优化 |

### 9.2 架构风险

| 风险 | 应对 |
|:---|:---|
| 领域模型复杂度 | 严格遵循 DDD，保持聚合根独立性 |
| 权限实现遗漏 | 全面测试权限矩阵，自动化权限测试 |
| 状态转换冲突 | 统一状态机模式，严格转换守卫 |

### 9.3 数据风险

| 风险 | 应对 |
|:---|:---|
| 数据一致性 | 使用事务、幂等操作 |
| 数据安全 | 最小共享、字段级脱敏 |
| 数据迁移 | 版本化迁移脚本、回滚策略 |
