## 第一章 产品理解

### 1.1 演立方是什么

演立方 V4.0 是 **AI驱动的企业活动内容供应链平台**。

它不是一个演员商城、不是演出资源交易网站、不是普通活动公司官网。它的本质是一个**企业活动解决方案基础设施**——将传统依靠人脉和经验的商演业务，通过AI和供应链管理能力实现数字化、标准化、规模化。

### 1.2 核心价值链

```
企业客户需求 → AI活动顾问分析 → 生成企业活动方案 → 商务成交 → 内容供应链匹配 → 项目交付 → 评价沉淀
```

这条链路的每一环都有设计挑战：

| 环节 | 设计挑战 | 核心设计目标 |
|------|---------|------------|
| 需求获取 | 企业客户不知道如何描述活动需求 | 降低认知门槛，引导式输入 |
| AI分析 | AI输出必须可控，不能脱离产品库乱报价 | 结构化输出 + 信心传达 |
| 方案生成 | 方案需要专业、可编辑、可导出 | 对话 + 侧栏预览双轨模式 |
| 商务成交 | 销售跟进混乱、回复慢、方案制作慢 | 销售工作台 + AI辅助闭环 |
| 供应链匹配 | 供应商质量参差不齐，匹配效率低 | AI匹配 + 分级认证 + 供应商档案 |
| 项目交付 | 交付缺少标准化管理 | 状态追踪 + 时间线 + 评价体系 |
| 评价沉淀 | 优质内容缺少可信背书 | 量化评分 + 案例库 + 数据资产 |

### 1.3 五端架构的设计含义

系统包含五个端，每个端的设计定位截然不同：

| 端 | 目标用户 | 设计定位 | 设计语言 |
|---|---------|---------|---------|
| 企业客户H5 | 企业HR、市场、保险从业者 | **信任入口**——让客户相信这是一个专业平台 | 商务质感 + 案例驱动 + AI引导 |
| AI销售工作台 | 内部商务/老板 | **效率引擎**——让销售更快成交 | 信息密度高 + AI嵌入式 + 数据驱动 |
| 供应商H5 | 演员、主持人、编剧、培训师 | **任务中心**——让供应商清晰履约 | 极简明确 + 移动优先 |
| 平台运营后台 | 运营、管理层 | **管控中枢**——全局可视 | 数据大盘 + 管理驾驶舱 |
| AI Agent中心 | 系统内部 | 不可见，但决定AI输出质量 | N/A |

**关键设计原则**：五端视觉统一但信息架构按角色分化。统一靠 Design System，分化靠角色化工作台。

### 1.4 与现有产品（销管家）的关系

销管家 V1 是一个快速验证的 MVP，已实现：
- 四端基础路由结构（41个路由文件）
- 商机管理核心流程
- AI对话基础能力（流式输出）
- 基础组件库（shadcn + Ant Design 混用）

**V4.0 设计策略必须解决 V1 的遗留问题**：
1. shadcn 和 Ant Design 双设计系统混用——必须统一为单一 Design System
2. 状态色硬编码（`<Tag color="gold">`）——必须收敛到 Design Token
3. AI置信度徽章仅在供应商端使用——必须全端拉齐
4. 缺少空态/骨架屏/错误态组件——必须补齐
5. 几乎无过渡动效——必须建立 Animation Token
6. 移动端交互深度不足——需要独立设计规范

## 第二章 用户分析

### 2.1 企业客户

**核心画像**：

| 维度 | 描述 |
|------|------|
| 行业 | 保险公司、金融机构、企业HR、品牌市场部门、商协会 |
| 场景 | 年会、团建、客户答谢会、增员会、表彰大会、品牌活动 |
| 决策模式 | 多人参与（发起人→审批人→执行人），周期1-4周 |
| 痛点 | 不知道办什么活动、不知道找谁、担心质量不可控、预算不透明 |

**设计 implications**：

1. **信任优先于效率**——企业客户第一次使用时，最关心的是"这个平台靠谱吗"，而非"我能多快下单"。首页设计必须先建立信任，再引导操作。
2. **案例是最好的说服力**——"XX保险公司300人年会用了脱口秀团建"比任何功能介绍都有效。案例卡片是客户端最重要的内容组件。
3. **AI是顾问而非工具**——企业客户期望的是"帮我推荐一个适合的活动方案"，而非"我自己在系统里搜索"。AI交互必须是对话式、引导式的。
4. **决策链路长**——从浏览到成交可能经历多人审批。设计方案需要支持"分享给同事/领导查看"的协作场景。
5. **行业敏感**——保险行业客户和互联网公司客户对"专业"的定义完全不同。信息架构需要支持行业场景化入口。

### 2.2 销售/老板

**核心画像**：

| 维度 | 描述 |
|------|------|
| 角色 | 内部商务人员、公司管理层 |
| 日常 | 微信沟通客户、整理需求、制作方案、跟进报价、协调供应商 |
| 痛点 | 回复慢（客户等不及）、方案制作慢（每次从零开始）、跟进混乱（忘记跟进） |
| 核心诉求 | 提高成交效率，减少重复劳动 |

**设计 implications**：

1. **AI销售助手是核心差异化**——不是通用的ChatGPT，而是嵌入在销售工作流中的专用AI。它能解析聊天记录、生成需求摘要、推荐产品组合、生成报价说明。
2. **商机漏斗必须一目了然**——销售需要在10秒内看到：哪些客户需要跟进、哪个阶段卡住了、今天该做什么。看板视图 + 今日待办是必须的。
3. **信息密度要高但不压迫**——销售是高频用户，可以承受比客户端更高的信息密度（参考 Linear 的设计哲学）。但"高密度"不等于"堆砌"，而是通过精细的排版层级和紧凑的间距实现。
4. **移动端是刚需**——销售经常在外拜访客户，需要移动版工作台查看商机、快速回复。

### 2.3 内容供应商

**核心画像**：

| 维度 | 描述 |
|------|------|
| 类型 | 脱口秀演员、即兴演员、主持人、编剧、培训师 |
| 诉求 | 稳定商业订单、档期管理、收入透明 |
| 技术水平 | 参差不齐，许多人对复杂App接受度低 |

**设计 implications**：

1. **极简至极**——供应商端应该只有核心动作：查看任务 → 确认接单 → 查看时间地点 → 完成履约 → 查看收入。任何多余功能都是干扰。
2. **移动优先**——供应商在演出场所使用手机，H5体验必须流畅。
3. **不暴露商业信息**——供应商不能看到客户成交价格，只能看到自己的收入。

### 2.4 平台运营

**核心画像**：

| 维度 | 描述 |
|------|------|
| 角色 | 运营人员、管理层 |
| 职责 | 管理产品SKU、供应商、订单、数据、AI反馈、权限 |
| 诉求 | 全局可视、快速定位问题、数据驱动决策 |

**设计 implications**：

1. **管理驾驶舱**——首页必须是数据大盘：商机数量、成交金额、待跟进客户、订单状态、毛利分析。
2. **信息架构按业务域组织**——销售→订单→供应链→财务，每个域有独立的子导航。
3. **AI反馈闭环**——运营需要看到AI推荐的准确率、采纳率、客户反馈，用于持续优化。

## 第三章 竞品研究

### 3.1 研究范围与方法

我们研究了四类共13个产品：

- **企业SaaS**：Salesforce、HubSpot、Linear、monday.com、Notion
- **AI产品**：ChatGPT、Claude、Cursor、Lovable
- **企业服务平台**：Fiverr Business、Upwork Enterprise、Shopify
- **活动管理**：Cvent、Eventbrite

研究聚焦五个维度：信息架构、工作台设计、AI交互、服务可信度、企业采购体验。

### 3.2 值得学习的设计模式

#### 3.2.1 信息架构

| 模式 | 来源 | 适用场景 | 借鉴方式 |
|------|------|---------|---------|
| 三栏后台布局（顶部操作 + 左导航 + 主内容） | Shopify/Cvent | 运营后台 | 作为后台基线布局 |
| 四阶段生命周期架构（规划→推广→执行→复盘） | Cvent | 活动项目全流程 | 嵌入内容供应链各环节 |
| Command Palette（Cmd+K全局搜索+操作） | Linear | 销售工作台 | 适配中文自然语言，作为AI入口 |
| 分步向导（Step-by-Step Wizard） | Eventbrite/Shopify | 客户首次创建活动 | 降低首次使用门槛 |
| 侧边栏 + 主内容区双栏 | ChatGPT/Claude | AI对话页面 | 对话 + 方案预览 |

#### 3.2.2 工作台设计

| 模式 | 来源 | 适用场景 | 借鉴方式 |
|------|------|---------|---------|
| "首页即检查清单"的渐进式引导 | Shopify | 新客户首次使用 | 首页展示待办进度和下一步 |
| 看板视图 + 拖拽操作 | HubSpot/monday.com | 商机漏斗管理 | 商机阶段拖拽推进 |
| 多视图无缝切换（表格/看板/时间线/日历） | monday.com | 活动项目管理 | 同一数据多维度查看 |
| 内联编辑（直接在列表中修改字段） | Linear/Notion | 高频操作场景 | 减少页面跳转，提升效率 |
| 仪表盘指标卡 + 趋势箭头 | 全部SaaS产品 | 全端首页 | 统一的Dashboard Widget |

#### 3.2.3 AI交互

| 模式 | 来源 | 适用场景 | 借鉴方式 |
|------|------|---------|---------|
| 底部居中输入栏 + 空白状态引导Chip | ChatGPT | 客户端AI入口 | "年终团建""客户答谢会"等快捷入口 |
| 对话 + 侧栏Artifacts双轨模式 | Claude | AI方案生成 | 左侧对话，右侧结构化方案预览 |
| 分阶段流式生成 | Lovable | 方案逐步构建 | 按模块逐一生成：概要→流程→预算→供应商 |
| 精细化用户控制（Accept/Reject/Checkpoint） | Cursor | 方案修改 | 支持整体/模块/字段三级修改粒度 |
| 版本历史管理 | Claude Artifacts | 方案迭代 | 每次修改自动保存版本，可回退 |
| AI执行过程透明化 | Cursor Agent | 信任建立 | 展示AI推理路径："基于50人规模和团建场景..." |

#### 3.2.4 服务可信度

| 模式 | 来源 | 适用场景 | 借鉴方式 |
|------|------|---------|---------|
| Logo信任墙 | Fiverr/Upwork/Cvent | 客户端首页 | 展示合作企业Logo |
| 分级认证徽章（Pro/Expert-Vetted） | Fiverr/Upwork | 供应商展示 | 认证/优选/顶级三级体系 |
| 量化数据信任（"平均X天完成""X%客户满意"） | Upwork/Cvent/Shopify | 全端 | 用真实运营数据替代空洞承诺 |
| 客户证言/案例研究 | 全部 | 客户端 | 带姓名、职位、企业名的真实案例 |
| AI能力品牌化包装（如CventIQ） | Cvent | 品牌层面 | 将AI能力独立品牌化展示 |

#### 3.2.5 企业采购体验

| 模式 | 来源 | 适用场景 | 借鉴方式 |
|------|------|---------|---------|
| RFP需求提案流程（发布需求→供应商方案→对比评审） | Cvent | 供应商匹配 | AI匹配 + 人工确认 |
| 多级服务包/定价体系 | Eventbrite | 产品定价 | 经济/推荐/升级三档方案 |
| 专属客户成功经理角色展示 | Fiverr/Upwork | 客户端 | 突出"有人帮你"的人性化服务 |
| 合规中心独立模块 | Fiverr Business/Upwork | 企业客户 | 版权审核、合同管理、发票 |

### 3.3 不适合演立方的模式

| 模式 | 来源 | 不适合的原因 |
|------|------|------------|
| Gig卡片式的"货架浏览"模式 | Fiverr | 活动内容供应链比标准化Gig复杂，不能简化为选品下单 |
| 过度鲜艳多彩的状态色系统 | monday.com | 大量高饱和色彩让界面显得"玩具化"，不适合金融/保险客户 |
| 纯暗色主题默认 | Linear | 活动管理面向的传统企业用户更习惯亮色主题 |
| 开放式人才市场搜索 | Upwork | 演立方的内容供应商应通过AI智能匹配，非企业自主搜索 |
| 过度定制化能力 | Salesforce | 初期产品不需要客户自定义品牌色等企业级定制 |
| 纯文档/内容管理定位 | Notion | 缺乏活动管理特有的流程管理能力 |
| $5起步的低价锚定 | Fiverr | 演立方面向企业级活动采购，应避免低价暗示 |
| "万能工具"定位 | Notion | 垂直B2B工具应更聚焦，降低学习曲线 |
| 完全开放的App生态 | Shopify | 内容供应链需要严格准入和质量管控 |
| 过度简化的活动创建（5步搞定） | Eventbrite | 企业活动内容需求远比"起个名字设个票价"复杂 |

### 3.4 演立方的独特设计语言

综合竞品研究，演立方应形成以下独特设计语言：

**"AI驱动的企业活动解决方案平台"不等于以上任何一种产品。** 它是：
- 比Salesforce更**轻量**——不需要CRM的复杂配置能力
- 比HubSpot更**垂直**——聚焦活动内容供应链，不做泛营销
- 比Linear更**温暖**——面向非技术用户，不能过于冷峻
- 比 Notion 更**聚焦**——功能明确呈现，不依赖用户自行探索
- 比Fiverr/Upwork更**一体化**——不是撮合平台，而是统一采购 + 交付管理
- 比Cvent更**AI原生**——AI不是附加功能，而是核心交互模式

**演立方的三个设计独创点**：

1. **AI活动顾问**：不是通用ChatBot，而是基于产品库、案例库、价格规则库的专用AI。对话引导 + 结构化方案预览的双轨模式。
2. **内容供应链可视化**：类似物流追踪，实时展示每个内容品类的生产进度、审核状态、交付节点。
3. **方案-报价-成交一体化**：从AI生成方案到报价发送到合同确认的端到端数字化闭环，在同类产品中没有先例。

## 第四章 设计定位

### 4.1 品牌关键词

**五个核心品牌关键词**（按权重排序）：

1. **专业 (Professional)** —— 企业客户第一感知。不是"专业做演出的"，而是"专业做企业活动解决方案的"。
2. **可信 (Trustworthy)** —— B2B交易的基石。每一个设计决策都要回答：这能让客户更信任我们吗？
3. **智能 (Intelligent)** —— AI不是噱头，而是真实提升效率的能力。设计要让AI的价值可感知、可验证。
4. **精准 (Precise)** —— AI匹配的准确性、方案推荐的针对性、报价的合理性。精准是效率的前提。
5. **从容 (Composed)** —— 企业客户使用演立方时，应该感到"活动这件事被安排好了"的从容感，而非焦虑和不确定。

### 4.2 视觉气质

**企业客户第一次打开产品时，应该感觉：**

> "这是一个成熟的企业级SaaS平台，和飞书、钉钉、企业微信是同一级别的产品。它懂企业活动，有AI能力，但不是花哨的AI玩具。它让我觉得把公司活动交给它处理是安全的。"

**气质关键词展开**：

| 气质维度 | 是 | 不是 |
|---------|---|------|
| 行业级别 | 企业级SaaS | 创业公司MVP |
| 专业度 | 咨询公司级别的方案呈现 | 活动公司的案例展示 |
| AI感知 | AI是安静的助手，在需要时出现 | AI是喧宾夺主的主角 |
| 创意感 | 克制的创意——在细节中体现品味 | 花哨的动画和渐变 |
| 温度 | 专业但不冰冷——有人的关怀感 | 机械的纯工具感 |

### 4.3 明确禁止的设计方向

以下视觉方向**严格禁止**，因为它们会严重损害品牌定位：

| 禁止方向 | 具体表现 | 为什么禁止 |
|---------|---------|----------|
| 廉价演出网站风格 | 大面积紫色渐变背景、星星特效、霓虹灯文字、演出海报式排版 | 暗示"低端娱乐"，与企业级定位冲突 |
| 娱乐资讯网站风格 | 密集的图文混排、瀑布流、热搜榜、标题党式推荐 | 暗示"内容消费平台"，而非解决方案平台 |
| 电商商城风格 | 商品卡片网格、价格标签醒目、"加入购物车"按钮、促销横幅 | 演立方不是卖商品的，是提供解决方案的 |
| 花哨AI玩具风格 | 大面积粒子动画、3D旋转logo、彩虹渐变、"AI魔法"式文案 | 企业客户需要的是可控的智能，不是炫技 |
| 传统活动公司官网风格 | 全屏轮播Banner、华丽但空洞的视觉、缺少功能深度 | 缺乏产品感，不像一个可用的工具 |

## 第五章 视觉方向

### 5.1 色彩战略

#### 5.1.1 色彩哲学

演立方的色彩体系遵循 **"克制的品牌表达 + 清晰的信息层级"** 原则：

- **品牌色不喧宾夺主**——品牌紫色只用于关键交互点（主按钮、链接、AI标识），大面积空间交给中性色。
- **中性色传递专业感**——参考 Notion 的温暖灰调哲学，使用带微妙暖色的中性色，而非冷调纯灰。
- **语义色精准传达状态**——参考 monday.com 的彩色状态系统，但降低饱和度，使其在专业场景中不显得轻浮。
- **AI有专属视觉标识**——AI生成的内容、AI操作的区域，有微妙但可识别的视觉区分（如AI标识色、AI背景色）。

**色彩设计决策说明**：

1. **Primary `#5B4FD6`**：在现有品牌紫 `#6E59F5` 基础上降低了明度和饱和度，使其在企业场景中更显沉稳。紫色传递"创新"和"品质"，但需要避免在中国文化中的非主流联想，因此往深蓝紫方向调整，增加专业感。

2. **Secondary `#1A1D2E`**：深邃的藏青色，而非纯黑。用于标题和强调文字，参考了 Notion 的 `#37352F` 哲学——带色调的深色比纯黑更有温度和品质感。

3. **中性背景采用冷灰而非暖灰**：与 Notion 不同，演立方的背景色系偏冷灰（`#F7F8FA`），因为暖灰更适合文档工具（纸质感），而冷灰更适合数据密集型的SaaS工具。

4. **AI专属色系**：AI能力需要视觉识别度。通过 `ai-bg`、`ai-border`、`ai-accent` 三个层级，让用户在不阅读文字的情况下就能识别"这是AI生成/操作的区域"。

5. **状态色降低饱和度**：相比 monday.com 的高饱和状态色，演立方的状态色饱和度降低约 20-30%，在保持可辨识度的同时维护专业感。

### 5.2 字体策略

#### 5.2.1 字体哲学

- **中文优先**：所有设计从中文排版出发，而非英文排版适配中文。
- **功能性优先**：选择字体的标准是屏幕可读性、信息密度友好、数字排版优秀，而非艺术性。
- **统一字栈**：五端使用完全相同的字体栈，确保品牌一致性。

**排版设计决策说明**：

1. **字重克制**：最多用到 700（Bold），标题用 600（Semi-bold），正文用 400（Regular）。不使用 300（Light）或 900（Black），保持信息层级清晰而不极端。

3. **数字专用 Token**：B2B SaaS 中数字出现频率极高（金额、人数、评分、指标）。独立的 Numeric Token 确保数字排版的一致性和专业感。

4. **Display 字号序列**：36/30/24 的梯度，在客户端展示页中创造视觉冲击力。工作台和后台不使用 Display 级别。

### 6.2 Design Token 实施规范

**命名规范**：采用 `--{category}-{property}-{variant}-{state}` 的四段式命名：

```
--color-primary                   → 品牌主色
--color-primary-hover             → 品牌主色悬停态
--color-text-secondary            → 次要文字色
--color-bg-surface                → 表面背景色
--color-status-won                → 已成交状态色
--shadow-ai                       → AI专属阴影
--radius-md                       → 中等圆角
--duration-normal                 → 标准动画时长
```

**Token 分层原则**：

1. **Global Token**（全局Token）：颜色值、字号值等原始值，如 `--gray-500: #5B6178`
2. **Semantic Token**（语义Token）：带业务含义的引用，如 `--text-secondary: var(--gray-500)`
3. **Component Token**（组件Token）：组件级覆盖，如 `--button-primary-bg: var(--color-primary)`

**V1.0 只定义 Global + Semantic 层，Component Token 在组件开发时逐步补充。**

### 6.3 五端设计变量

虽然 Design System 统一，但五端有不同的设计变量配置：

| 变量 | 客户端 | 销售工作台 | 供应商端 | 运营后台 |
|------|-------|----------|---------|---------|
| 信息密度 | 低（宽松） | 高（紧凑） | 中 | 中高 |
| 默认字号基准 | 16px | 14px | 15px | 14px |
| 卡片内边距 | 24px | 16px | 20px | 16px |
| 列表行高 | 宽松 | 紧凑 | 中等 | 中等 |
| AI元素占比 | 高 | 高 | 低 | 中 |
| 导航模式 | 底部Tab + 顶部栏 | 侧边栏 + 顶部栏 | 底部Tab | 侧边栏 |
| 响应式断点 | 移动优先 | 桌面优先 | 移动优先 | 桌面优先 |

## 第七章 组件规范

### 7.1 组件体系总览

以下规划 V1.0 的核心业务组件。每个组件从"使用场景"、"状态"、"交互逻辑"三个维度定义。

### 7.2 AI Assistant Card（AI助手卡片）

**使用场景**：
- 客户端：AI活动顾问对话气泡
- 销售工作台：AI销售助手建议卡片
- 运营后台：AI分析结果展示

**状态**：
- `idle` — 空闲，等待用户输入
- `thinking` — AI正在思考（显示脉冲动画）
- `streaming` — AI正在流式输出内容
- `complete` — 输出完成，显示操作按钮
- `error` — 输出失败，显示重试按钮
- `edited` — AI内容被人工修改过（显示"已编辑"标记）

**交互逻辑**：
- 用户输入后，卡片先进入 `thinking` 状态，展示三点脉冲动画
- 流式输出期间，内容区域逐段淡入（`ai-stream` 动画）
- 输出完成后，底部渐显操作按钮组：复制、重新生成、反馈（有用/无用）、编辑
- 如果输出包含结构化内容（方案、报价），右侧触发 Artifacts 面板
- AI输出的关键数字（价格、人数、时间）使用 `numeric-md` + `text-primary` 高亮
- AI内容区域使用 `ai-bg` 底色 + `ai-border` 边框，建立视觉识别

**设计规范**：
- AI消息气泡使用 `radius-2xl`（24px），区别于用户消息的 `radius-lg`（12px）
- AI气泡左上角带 AI 标识图标（小圆形品牌色图标），不用头像
- 用户消息右对齐，品牌色背景 + 白色文字
- AI消息左对齐，浅色背景 + 深色文字

### 7.3 Solution Card（方案卡片）

**使用场景**：
- 客户端方案推荐列表
- 销售工作台方案选择
- 方案对比视图

**状态**：
- `recommended` — AI推荐（带"AI推荐"徽章）
- `economy` / `standard` / `premium` — 三档方案（经济/推荐/升级）
- `selected` — 当前选中方案
- `rejected` — 已被排除的方案
- `expired` — 报价已过期

**交互逻辑**：
- 卡片展示：方案名称、适用场景、人数范围、时长、总价、AI推荐理由
- Hover 时显示"查看详情"操作
- 点击展开为详情面板（Drawer或侧栏）
- 三档方案并排展示时，推荐方案默认居中且略大，视觉引导选择
- 方案包含的供应商/演员以小头像列表展示（最多显示4个 + "+N"）
- AI置信度以微型徽章显示在卡片右上角（高/中/低三档）

**设计规范**：
- 标准卡片使用 `radius-lg` + `shadow-sm`
- Hover 状态 `shadow-md` + `border-strong`
- 推荐方案卡片边框使用 `primary` 色
- 三档方案并排时，推荐方案使用 `primary-subtle` 背景

### 7.4 Case Card（案例卡片）

**使用场景**：
- 客户端首页案例展示
- 客户端案例中心列表
- 销售工作台发送给客户的案例推荐

**状态**：
- `default` — 默认展示
- `featured` — 精选案例（首页轮播或置顶）
- `industry-tagged` — 按行业标签筛选

**交互逻辑**：
- 卡片展示：封面图（活动现场照片）、企业Logo、活动类型标签、参与人数、客户评价摘要
- Hover 时封面图微微放大（scale 1.02，200ms ease-out）
- 点击进入案例详情页
- 案例卡片支持"分享给同事"操作（生成分享链接或小程序码）
- 案例中引用的具体方案和供应商可点击跳转

**设计规范**：
- 封面图比例 16:9，使用 `object-fit: cover`
- 企业Logo尺寸 32x32px，圆角 `radius-sm`
- 活动类型标签使用 `caption` 字号 + 对应行业状态色
- 底部展示客户姓名 + 职位 + 企业名，建立真实感

### 7.5 CRM Opportunity Card（商机卡片）

**使用场景**：
- 销售工作台商机列表（表格行或卡片视图）
- 看板视图中的商机卡片
- 今日待办中的商机提醒

**状态**：
对应商机管道的8个阶段：
- `新线索` → `已联系` → `需求确认` → `已方案` → `已报价` → `谈判中` → `已成交` → `已完成/待复购`
- 另加 `已丢单` 终态

**交互逻辑**：
- 列表视图：紧凑行展示（客户名、活动类型、预算、状态Tag、负责人、最后跟进时间）
- 卡片视图：更多字段可见（客户行业、AI匹配分、跟进记录摘要）
- 看板视图：最精简（客户名 + 活动类型 + 预算 + 优先级标记），支持拖拽切换状态
- 支持内联编辑状态（点击状态Tag弹出下拉选择）
- 点击进入商机详情页
- 卡片左侧使用 3px 色条标识状态色，一目了然

**设计规范**：
- 状态Tag使用对应 `status-*` 颜色，`radius-sm`，`caption` 字号
- 优先级使用图标 + 文字：高（红色向上箭头）、中（橙色横线）、低（灰色向下箭头）
- AI匹配分使用微型进度条 + 数字展示
- 最后跟进时间超过48小时的卡片，时间文字变为 `text-tertiary` + "超时"提示

### 7.6 Dashboard Widget（仪表盘指标卡）

**使用场景**：
- 销售工作台首页（个人/团队指标）
- 运营后台大盘
- 供应商端收入概览

**状态**：
- `positive` — 正向趋势（绿色向上箭头）
- `negative` — 负向趋势（红色向下箭头）
- `neutral` — 持平（灰色横线）
- `loading` — 数据加载中（骨架屏）

**交互逻辑**：
- 展示：指标名称、核心数值、环比变化（百分比 + 趋势箭头）、迷你趋势图（可选）
- 点击可下钻到详细数据页
- 数值使用 `numeric-lg` + `text-primary`
- 趋势箭头和百分比使用对应语义色
- 环比文字格式："较上月 +12%" 或 "较上周 -3%"

**设计规范**：
- 卡片尺寸：最小 200px 宽，高度自适应
- 内边距 `padding-card`（24px）
- 指标名称 `body-sm` + `text-secondary`
- 核心数值 `numeric-lg` + `text-primary`
- 趋势区域 `caption` + 语义色

### 7.7 Supplier Card（供应商卡片）

**使用场景**：
- 运营后台供应商/演员管理
- 销售工作台供应商检索（P0缺失能力）
- AI方案中的供应商推荐

**状态**：
- `available` — 可接单（档期空闲）
- `busy` — 档期紧张
- `unavailable` — 不可用（档期满或暂停合作）
- `pending-review` — 待审核（新申请供应商）

**交互逻辑**：
- 卡片展示：头像、姓名、品类标签、城市、评分（星级）、历史完成单数、档期状态
- 运营后台：完整信息 + 编辑/操作按钮
- 销售端：精简信息 + "加入方案"操作
- AI方案中：极简展示（姓名 + 品类 + 评分），点击展开详情
- 评分使用星级 + 数字双展示："4.8 (32单)"
- 认证等级徽章显示在头像右上角

**设计规范**：
- 头像 48x48px，`radius-full`
- 品类标签使用 `caption` + `primary-subtle` 背景 + `primary` 文字
- 评分数字使用 `font-mono` + `numeric-sm`
- 档期状态用颜色点 + 文字：绿色"空闲"、橙色"紧张"、灰色"不可用"

### 7.8 Quote Card（报价卡片）

**使用场景**：
- 销售工作台报价列表
- 商机详情中的报价版本历史
- 客户端报价查看

**状态**：
- `draft` — 草稿
- `sent` — 已发送给客户
- `viewed` — 客户已阅
- `confirmed` — 客户已确认
- `void` — 已作废

**交互逻辑**：
- 卡片展示：报价编号、客户名、活动类型、总金额、毛利、状态、有效期
- 支持多版本对比（选择两个版本并排展示差异）
- 发送给客户后展示"已发送" + 发送时间 + 客户阅读状态
- 客户确认后状态自动更新，触发后续流程
- 毛利信息仅在销售/运营端可见，客户端不展示

**设计规范**：
- 金额使用 `numeric-md` + `font-mono`
- 毛利为正时使用 `success` 色，为负时使用 `error` 色
- 状态Tag遵循 `status-*` 色系
- 多版本时使用时间线组件串联

### 7.9 Timeline（时间线）

**使用场景**：
- 商机跟进记录
- 订单履约进度
- 供应商任务状态
- 报价版本历史

**状态**：
- `completed` — 已完成（实心圆点 + 连接线）
- `current` — 当前步骤（实心圆点 + 品牌色 + 脉冲动画）
- `pending` — 待进行（空心圆点 + 虚线连接）
- `failed` — 失败/异常（实心红色圆点）

**交互逻辑**：
- 垂直时间线布局，左侧时间 + 右侧内容卡片
- 每个节点展示：时间戳、操作人、动作描述、详细内容（可折叠）
- AI操作节点带 AI 标识图标，区分人工操作
- 支持在时间线中直接"添加跟进记录"
- 当前节点有微弱的脉冲动画，引导注意力

**设计规范**：
- 连接线宽度 2px，颜色 `border-default`
- 节点圆点直径 10px（完成态）、10px（当前态）、10px（待进行态）
- 当前态使用 `primary` 色填充
- 时间戳 `caption` + `text-tertiary`
- 操作人使用 Avatar（24px）+ 姓名

### 7.10 Review Card（评价卡片）

**使用场景**：
- 供应商档案页的评价列表
- 案例详情页的客户评价
- 运营后台评价管理

**状态**：
- `positive` — 好评（4-5星）
- `neutral` — 中评（3星）
- `negative` — 差评（1-2星）
- `pending` — 待评价（活动已结束，客户尚未评价）

**交互逻辑**：
- 卡片展示：客户姓名（可匿名）、企业名、活动类型、星级评分、评价内容、评价时间
- 维度评分以雷达图或条形图展示（专业度、内容质量、现场表现、商务表现、推荐意愿）
- 运营后台可对评价进行回复
- 供应商端仅展示好评（或经过处理的评价），保护供应商积极性

**设计规范**：
- 星级使用品牌金色 `#D4A017`
- 评价内容 `body-md`，最多展示3行，超出"展开全文"
- 维度评分使用微型条形图，宽度按百分比

### 7.11 Status Tag（状态标签）

**使用场景**：
- 全端所有需要展示状态的地方（商机、订单、报价、供应商等）

**状态**：
- 商机状态：新线索、已联系、需求确认、已方案、已报价、谈判中、已成交、已丢单、已结束
- 报价状态：草稿、已发送、已阅、已确认、已作废
- 供应商状态：空闲、紧张、不可用、待审核
- AI置信度：高、中、低

**交互逻辑**：
- 纯展示组件，不可交互
- 点击状态Tag可弹出状态变更操作（仅在有权限的端）
- AI置信度Tag使用专属样式（AI标识 + 渐变背景）

**设计规范**：
- 统一使用 Design Token 中的 `status-*` 色值，**严禁硬编码颜色**
- V1 必须消灭所有 `<Tag color="gold">` 式的硬编码
- 尺寸：`caption` 字号，高度 22px，内边距 2px 8px
- 圆角 `radius-sm`
- AI置信度Tag：背景使用 `primary-subtle`，文字使用 `primary`，左侧带 AI 小图标

### 7.12 AI Confidence Badge（AI置信度徽章）

**使用场景**：
- AI方案推荐卡片
- AI需求分析结果
- AI供应商匹配建议
- AI销售助手输出

**状态**：
- `high` — 高置信度（AI对结果有较高把握）
- `medium` — 中置信度（部分信息不确定）
- `low` — 低置信度（信息不足，建议人工确认）

**交互逻辑**：
- 纯展示组件
- `high`：绿色系，文案"高置信度"
- `medium`：橙色系，文案"需确认"
- `low`：红色系，文案"建议人工核实"
- 低置信度结果旁边应显示"人工审核"按钮
- Hover 显示AI的推理说明（Tooltip）

**设计规范**：
- 使用对应的语义色（`success`/`warning`/`error`）的 bg + border
- 文字使用对应语义色 + `caption` 字号
- 左侧带微型AI图标
- 动画：出现时使用 `ease-spring` 弹性效果

### 7.13 Trust Signal Bar（信任信号条）

**使用场景**：
- 客户端首页顶部

- `static` — 静态展示信任信息

- Logo尺寸 24-32px 高度

## 附录 A：与现有代码的映射关系

### A.1 需要统一的冲突

| 冲突点 | 现状（销管家V1） | V4.0 策略 |
|--------|----------------|----------|
| 双设计系统 | shadcn + Ant Design 混用 | 统一为单一 Design System，Ant Design 仅作为运营后台的选择 |

| 状态色硬编码 | `<Tag color="gold">` 等 | 全部收敛到 `status-*` Token |
| 字体栈 | 仅有基础定义 | 完整 Typography Token（Display/Heading/Body/Caption/Numeric） |
| 动效 | 仅AI三点脉冲 | 完整 Animation Token |
| AI置信度 | 仅供应商端 | 全端统一组件 |
| 空态/骨架屏 | 缺失 | V1.0 必须补齐 Skeleton 组件 |
| 响应式 | 断点不一致 | 统一断点：640/768/1024/1280/1536 |

### A.2 Token 命名与代码映射

V4.0 Design Token 将通过 CSS 自定义属性实现，直接映射到 Tailwind 的 `@theme` 配置中，确保设计系统与开发实现的一致性。
