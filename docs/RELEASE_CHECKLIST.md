# 演立方 MVP 手工发布检查清单

> 正式生产发布必须由项目负责人确认。任何 Agent 不得自动部署生产、删除生产数据或自主执行不可逆 Migration。

## 当前发布状态

现有 `backend/docker-compose.yml`、`deploy.sh`、Nginx 和 Fastify 配置存在构建目录、3001/3002 端口、`/health`/`/v1/health` 路径及 Migration 执行不一致。修复并在 Preview 完整验证前，**当前没有可靠的生产发布路径**。

## 1. 发布输入

- [ ] 发布版本与目标环境明确。
- [ ] 当前生效 PRD、包含的 F 编号和排除项明确。
- [ ] 待发布 Commit/Tag 唯一且可复现。
- [ ] `PROJECT_STATUS.md` 中无未解决的发布阻塞。
- [ ] 每个包含任务已有独立审查通过结论。

## 2. 最低检查

```bash
node scripts/check-governance.mjs
bash scripts/pre-commit-check.sh
```

- [ ] 命令实际执行并全部通过。
- [ ] Tenant 越权、角色权限、客户版/内部版和演员授权测试通过。
- [ ] 报价、合同金额、收款和状态机测试通过。
- [ ] 核心用户流程在 Preview 环境走通。
- [ ] 无 Mock、测试数据或 TODO 被当成生产能力。

## 3. 数据与回滚

- [ ] 数据库变更有新增 Migration，不改写历史 Migration。
- [ ] 已备份目标数据，备份可读取。
- [ ] 正向 Migration 已在 Preview 运行。
- [ ] 回滚 SQL/兼容方案已验证；不可逆项已进入老板决策卡。
- [ ] 上一稳定 Tag/Commit、配置和构建产物可立即恢复。

## 4. 老板确认

- [ ] 总调度已用老板决策卡说明用户影响、发布内容、已知风险和回滚方式。
- [ ] 项目负责人明确回复“同意推荐方案”或对应选项。
- [ ] 未获得确认前没有执行生产命令。

## 5. 手工发布

- [ ] 记录操作人、时间、环境、Commit/Tag 和 Migration。
- [ ] 按已验证的手工步骤部署，不临场改命令。
- [ ] 不在生产直接调试、修改数据或补写 Schema。
- [ ] 任何异常立即停止后续步骤，按回滚方案处理。

## 6. 发布后冒烟

- [ ] 健康检查正常。
- [ ] 登录与角色权限正常。
- [ ] Tenant A 无法访问 Tenant B 数据。
- [ ] 需求 → Brief → 方案 → 客户版核心链路正常。
- [ ] 报价、合同、收款和状态更新未异常。
- [ ] 错误日志无新增高严重度问题。
- [ ] `PROJECT_STATUS.md`、`CHANGELOG.md`、`versions.json` 已按实际发布结果更新。

## 7. 回滚完成条件

- [ ] 服务恢复到上一稳定版本。
- [ ] 数据完整性和核心流程重新验证。
- [ ] 回滚原因、影响、后续修复任务已记录。
- [ ] 如涉及重大策略变化，更新 `DECISIONS.md`。
