## 1. 按钮反馈

### 1.1 按钮类型定义

演立方 V4.7 按钮体系基于 Ant Design 6 Button 组件，通过 `type` 与 `danger` 属性组合形成 4 种按钮类型：

| 类型 | AntD 映射 | 用途 | 示例场景 |
|------|-----------|------|----------|
| **Primary** | `type="primary"` | 主操作 — 页面唯一主焦点 | "获取方案"、"发送"、"提交" |
| **Secondary** | `type="default"` | 次要操作 — 辅助主操作 | "查看详情"、"重新生成"、"取消" |
| **Ghost** | `type="text"` / `type="link"` | 文字/链接操作 — 列表内行级操作 | "编辑"、"删除"、"查看全部" |
| **Danger** | `type="primary"` + `danger` 或 `type="default"` + `danger` | 破坏性操作 | "删除方案"、"撤销分配" |

> **[已知问题]** Agent 首页"让 AI 推荐"按钮使用 `var(--yl-success)` 绿色背景，违反品牌色唯一性原则。必须替换为 Primary 类型 `#5B4FD6`。

### 1.2 按钮交互态规范

以下表格定义每种按钮类型在 5 种交互态下的完整视觉表现。

#### Primary 按钮

|--------|----------|----------|--------|----------|
| Default | 背景 `#5B4FD6`，文字 `#FFFFFF`，圆角 8px，高度 40px | — | — | `Button type="primary"` |
| Hover | 背景过渡至 `#4A3FC5`，阴影增强 `--yl-shadow-sm` | 150ms | `cubic-bezier(0.4,0,0.2,1)` | `&:hover` |
| Active | 背景过渡至 `#3D33B3`，阴影收至 `--yl-shadow-none`，轻微缩放 `scale(0.98)` | 100ms | `cubic-bezier(0.4,0,0.2,1)` | `&:active` |
| Disabled | 背景 `#C5C2E8`，文字 `#FFFFFF` 降至 opacity 0.6，cursor `not-allowed` | 0ms | — | `disabled` 属性 |
| Loading | 背景保持 `#5B4FD6`，左侧出现 `Loading` 图标（14px 白色旋转），文字保留，按钮不可再次点击 | 图标旋转 800ms/圈 | `linear` | `loading` 属性 |

### 1.3 按钮组合规则

- **同一行内** 最多 1 个 Primary + 2 个 Secondary，其余使用 Ghost
- **Primary 始终在最右**（对话框场景）或**最左**（表单页底部操作栏）
- **Danger 按钮** 与其他按钮之间需 16px 间距分隔，不可紧邻 Primary
- **图标按钮**（如"发送" `SendOutlined`）图标在左、文字在右，间距 8px

### 1.4 尺寸规范

| 尺寸 | 高度 | 内边距 (px) | 字号 | 适用场景 |
|------|------|-------------|------|----------|
| `large` | 44px | 16/24 | 16px | 首页/落地页主 CTA |
| `middle`（默认） | 40px | 12/20 | 14px | 常规页面操作 |
| `small` | 32px | 8/16 | 13px | 卡片内、工具栏操作 |

## 2. 页面过渡

### 2.1 页面进入 (Page Enter)

路由切换时，新页面内容区执行淡入动画。

| 属性 | 值 | Token |
|------|----|-------|
| Duration | 150ms | `--yl-duration-fast` |
| Easing | `cubic-bezier(0,0,0.2,1)` | `--yl-ease-out` |
| 效果 | `opacity: 0 → 1` + `translateY(8px → 0)` | — |

```
路由切换前          路由切换后 (0ms)        过渡中 (75ms)         完成 (150ms)
┌────────────┐     ┌────────────┐         ┌────────────┐        ┌────────────┐
│            │     │ ░░░░░░░░░░ │         │ ▓▓▓▓▓▓▓▓▓▓ │        │ ██████████ │
│  旧页面     │ →   │  新页面     │  →      │  新页面     │  →     │  新页面     │
│  内容       │     │  opacity:0 │         │  opacity:.5│        │  opacity:1 │
│            │     │  translateY│         │  translateY│        │  translateY│
│            │     │  (8px)     │         │  (4px)     │        │  (0)       │
└────────────┘     └────────────┘         └────────────┘        └────────────┘
```

**实现方式**:

```css
.yl-page-enter {
  animation: yl-page-fade-in 150ms var(--yl-ease-out) both;
}

@keyframes yl-page-fade-in {
  from { opacity: 0; transform: translateY(8px); }
  to   { opacity: 1; transform: translateY(0); }
}
```

> **[已知问题]** TDDP 规范要求页面过渡 150ms 淡入，当前代码库尚未实现路由级过渡动画。需在 TanStack Router 的 `onEnter` 生命周期中注入 `.yl-page-enter` 类名。

### 2.2 卡片交错入场 (Card Stagger)

列表/网格中的卡片以交错延迟方式逐张入场，营造内容「铺展」感。

| 属性 | 值 | Token |
|------|----|-------|
| 单卡 Duration | 350ms | `--yl-duration-slow` |
| 单卡 Easing | `cubic-bezier(0,0,0.2,1)` | `--yl-ease-out` |
| 交错延迟 | 50ms / 张 | — |
| 单卡效果 | `opacity: 0→1` + `translateY(12px→0)` | — |

```
时间轴 →   0ms        50ms       100ms      150ms      200ms      250ms ...

Card 1:   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
Card 2:   ░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
Card 3:   ░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
Card 4:   ░░░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
Card 5:   ░░░░░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
Card 6:   ░░░░░░░░░░▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░
           └─── 每张卡片延迟比上一张多 50ms ───┘
```

**实现方式**（SolutionCard 代码库已有模式）:

```css
.yl-card-enter {
  animation: yl-card-enter 350ms var(--yl-ease-out) both;
}

/* 第 i 张卡片: animation-delay: calc(i * 50ms) */
```

**规则**:
- 交错延迟最多到第 10 张（500ms），超出部分不再增加延迟
- 卡片数量 > 10 时，第 10 张之后同时入场
- 筛选/搜索结果更新时重新触发交错入场

### 2.3 区块揭示 (Section Reveal)

页面内非首屏区块滚动进入视口时执行揭示动画。

| 属性 | 值 |
|------|----|
| Duration | 250ms (`--yl-duration-normal`) |
| Easing | `cubic-bezier(0,0,0.2,1)` (`--yl-ease-out`) |
| 效果 | `opacity: 0→1` + `translateY(20px→0)` |
| 触发 | `IntersectionObserver`，元素 10% 进入视口时触发 |
| 一次性 | 是 — 揭示后不再重复 |

```
滚动前 (区块在视口下方)          滚动后 (区块进入视口)
                                 │
┌──────────────────────┐         │ ← 视口顶边
│   可见内容            │         │
│                      │         │
└──────────────────────┘         │
                                 │
  ░░░░░░░░░░░░░░░░░░░░  →        │ ┌──────────────────────┐
  ░░ 下一区块 (隐藏) ░░          │ │  下一区块 (揭示)     │
  ░░ opacity:0        ░░         │ │  opacity:1           │
  ░░ translateY(20px) ░░         │ │  translateY(0)       │
                                 │ └──────────────────────┘
```

## 3. 表单验证

### 3.1 验证时机

演立方 V4.7 表单验证遵循「渐进式验证」原则，根据用户操作阶段选择不同验证时机。

| 验证时机 | 触发条件 | 适用场景 | 反馈方式 |
|----------|----------|----------|----------|
| **实时验证** | 输入内容变化后 300ms 防抖 | 密码强度、用户名唯一性、邮箱格式 | 输入框下方即时提示 |
| **失焦验证** | 输入框失去焦点 (`onBlur`) | 必填项、格式校验（手机号、金额） | 输入框下方提示 + 红色边框 |
| **提交验证** | 点击提交按钮 / `Cmd+Enter` | 提交前的全量校验 | 滚动定位到第一个错误字段 |

### 3.2 验证流程图

```
用户输入
  │
  ├─ onChange 触发 ──→ 300ms 防抖 ──→ 格式校验通过？
  │                                      ├─ 是 → 清除错误，显示成功态（绿勾）
  │                                      └─ 否 → 不显示错误（等待失焦）
  │
  ├─ onBlur 触发 ──→ 完整校验通过？
  │                      ├─ 是 → 显示成功态（绿勾 icon）
  │                      └─ 否 → 显示错误（红字 + 红边框）
  │
  └─ onSubmit 触发 ──→ 全量校验所有字段
                         ├─ 全部通过 → 提交
                         └─ 有错误 → 滚动到第一个错误字段 + 聚焦
```

### 3.3 错误展示规范

#### 视觉规范

| 元素 | 规格 | 颜色 |
|------|------|------|
| 输入框边框 | 1.5px solid | `#C53030` (`--yl-error`) |
| 错误文字 | 13px / 20px line-height | `#C53030` (`--yl-error`) |
| 错误图标 | `ExclamationCircleOutlined` 14px | `#C53030` |
| 间距 | 错误文字距输入框底部 4px | — |

#### ASCII 示意

```
正常态                           错误态                           成功态
┌────────────────────────┐      ┌────────────────────────┐      ┌────────────────────────┐
│ 请输入活动名称          │      │ 活动名称                │      │ 2024年度客户答谢会 ✓    │
│ #D9DBE3 边框            │      │ #C53030 红色边框 1.5px  │      │ #00875A 绿色边框        │
└────────────────────────┘      └────────────────────────┘      └────────────────────────┘
                                 ⚠ 请输入活动名称（必填）          ✓ 名称可用
                                   #C53030 13px                    #00875A 13px
```

### 3.4 错误文案规范

| 规则 | 示例 | 说明 |
|------|------|------|
| 指明具体问题 | "请输入活动名称" | 不使用"输入有误"等模糊表述 |
| 指明正确格式 | "手机号需为 11 位数字" | 格式类错误必须给出格式说明 |
| 指明约束范围 | "预算金额需在 1,000 — 500,000 之间" | 范围类错误必须给出边界 |
| 不使用感叹号 | "两次输入的密码不一致" | B2B 场景语气克制 |
| 不使用「您」 | "请输入" 而非 "请您输入" | 简洁直接 |

### 3.5 成功展示规范

| 元素 | 规格 | 颜色 |
|------|------|------|
| 输入框边框 | 1px solid | `#00875A` (`--yl-success`) |
| 成功图标 | `CheckCircleOutlined` 14px | `#00875A` |
| 成功文字 | 13px（仅必要时显示） | `#00875A` |

> **注意**: 成功态仅在校验通过后短暂展示。如果该字段无特殊校验需求（如普通文本输入），失焦后仅需清除错误态，不必显示绿勾，避免视觉噪音。

## 4. 搜索行为

### 4.1 搜索模式定义

| 模式 | 触发方式 | 适用场景 | 反馈方式 |
|------|----------|----------|----------|
| **即时搜索** | 输入后 300ms 防抖触发 | 方案发现、商机列表、跟进中心 | 结果区原地刷新 |
| **回车搜索** | 按 `Enter` 键立即触发 | 所有搜索框（跳过防抖） | 结果区原地刷新 |
| **清除搜索** | 点击输入框右侧 `×` 按钮 | 搜索框有内容时 | 重置结果至未筛选状态 |

### 4.2 即时搜索规范

```
用户输入 "年度"
  │
  ├─ 第 1 个字符 "年" ──→ 重置 300ms 计时器
  ├─ 第 2 个字符 "度" ──→ 重置 300ms 计时器
  │
  ├─ 300ms 内无新输入 ──→ 触发搜索请求
  │                        │
  │                        ├─ 搜索中: 输入框右侧显示 Spin (14px)
  │                        ├─ 结果区: 保持旧结果 + 轻微遮罩 opacity 0.6
  │                        └─ 完成: 结果区刷新为新结果 + 卡片交错入场
  │
  └─ 用户按 Enter ──→ 立即触发搜索（跳过 300ms 等待）
```

> **[已知问题 — 必须修复]** 方案发现页搜索框当前使用 `onChange` 即时筛选，**无 300ms 防抖**，每次按键即触发过滤计算。跟进中心 `Input.Search` 同样缺少防抖。TDDP 规范要求所有即时搜索必须 300ms 防抖，避免高频渲染导致的性能问题。修复方案：
> ```typescript
> // 使用 useDebouncedCallback 或 lodash.debounce
> const debouncedSearch = useMemo(() => debounce(handleSearch, 300), []);
> <Input onChange={(e) => debouncedSearch(e.target.value)} />
> ```

│  🔍  搜索方案名称、标签...              ✕            │
│  ↑                                      ↑            │
│  SearchOutlined 前缀                  allowClear     │
│  #8B92A8 16px                         仅在有内容时    │
│                                       显示，#8B92A8  │
│                                                       │
│  背景: #FFFFFF                                         │
│  边框: #D9DBE3 1px → hover #5B4FD6                    │

### 4.4 搜索占位符文案规范

| 页面 | 占位符文案 | 说明 |
|------|-----------|------|
| 方案发现 | "搜索方案名称、标签..." | 指明可搜索的字段范围 |
| 跟进中心 | "搜索客户名称、商机名称..." | 指明可搜索的字段范围 |

**文案规则**:
- 使用 `搜索XX、XX...` 句式，列出 2-3 个可搜索字段
- 以 `...` 结尾暗示可输入更多
- 不使用"请输入"前缀（搜索框非必填项）

### 4.5 搜索结果反馈

| 场景 | 反馈 |
|------|------|
| 搜索中 | 输入框右侧 14px Spin，结果区遮罩 `opacity: 0.6` |

| 无结果 | 切换至 Empty 状态（详见 [07-页面状态规范](./07-页面状态规范.md)） |
| 搜索词清空 | 恢复至未筛选的完整列表 |

## 5. 筛选联动

### 5.1 筛选模式

| 模式 | 触发方式 | 适用场景 | 说明 |
|------|----------|----------|------|
| **即时筛选** | `onChange` 直接触发 | Select 下拉选择、Segmented 切换、Slider 拖动 | 选择即生效，无需确认 |
| **多筛选组合** | 多个筛选器同时生效 | 方案发现（4 Select + Slider）、跟进中心（Segmented） | 多个筛选条件之间为 **AND** 逻辑 |
| **筛选清空** | 点击"清空筛选"按钮 | 所有含筛选器的列表页 | 一键重置全部筛选条件 |

### 5.3 多筛选组合逻辑

```
筛选条件叠加 (AND 逻辑):

  Select: 活动类型 = "会议"
       AND
  Select: 场地偏好 = "室内"
       AND
  Select: 交付周期 = "1个月内"
       AND
  Slider: 预算范围 = [50000, 100000]
       AND
  Search: 关键词 = "年度"

  = 同时满足以上所有条件的方案
```

**规则**:
- 所有筛选器之间为 **AND** 关系，不支持 OR
- 同一 Select 内多选时，选项之间为 **OR** 关系（如活动类型选"会议"+"团建"）
- 筛选器即时生效，不需要额外"确认"按钮
- 每次筛选变化触发结果列表刷新 + 卡片交错入场

## 7. 拖拽排序

### 7.1 适用范围

拖拽排序**仅限** Supplier 端作战台（`/supplier/workspace`）商机列表，用于手动调整商机优先级。其他页面不启用拖拽。

### 7.2 拖拽配置

| 配置项 | 值 | 说明 |
|--------|----|------|
| 库 | `@dnd-kit/core` + `@dnd-kit/sortable` | 已在代码库中使用 |
| 传感器 | `PointerSensor` | 鼠标 + 触摸统一处理 |
| 激活约束 | `distance: 4px` | 移动超过 4px 才触发拖拽，避免误触点击 |
| 拖拽方向 | 垂直 | `restrictToVerticalAxis` |

### 7.3 拖拽视觉反馈

```
拖拽前 (正常列表)              拖拽中 (卡片被提起)            释放后

┌──────────────────┐          ┌──────────────────┐         ┌──────────────────┐
│ ★ 商机 A          │          │                  │         │ ★ 商机 B          │
│   客户：XX科技     │          │  ┌──────────────┐│         │   客户：YY集团     │
├──────────────────┤          │  │ ★ 商机 B      ││ ← 被拖拽 │ ├──────────────────┤
│ ★ 商机 B          │   ──→    │  │  客户：YY集团 ││   卡片   │ ★ 商机 A          │
│   客户：YY集团     │          │  │              ││         │   客户：XX科技     │
├──────────────────┤          │  │ opacity: 0.9 ││         │ ├──────────────────┤
│ ★ 商机 C          │          │  │ shadow: 12px ││         │ ★ 商机 C          │
│   客户：ZZ公司     │          │  └──────────────┘│         │   客户：ZZ公司     │
└──────────────────┘          │                  │         └──────────────────┘
                               │  ↓ 其余卡片让位  │
                               │  (平滑过渡 250ms)│
                               └──────────────────┘
```

#### 被拖拽卡片样式

| 属性 | 值 | Token |
|------|----|-------|
| 透明度 | `0.9` | — |
| 阴影 | `0 8px 24px rgba(91,79,214,0.16)` | 自定义（品牌色阴影） |
| 缩放 | `scale(1.02)` | 轻微放大强调 |
| 光标 | `grabbing` | — |
| 过渡 | 250ms `--yl-ease-out` | — |

#### 占位区域

其余卡片在拖拽过程中平滑移动让位，使用 `transition: transform 250ms var(--yl-ease-out)`。

### 7.4 拖拽完成行为

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | `onDragEnd` 触发 `arrayMove` | 更新数据数组顺序 |
| 2 | 排序模式自动切换为"最近更新" | Segmented 切换，脱离"推荐排序" |
| 3 | 显示 Toast 提示 | `message.info("已切换为手动排序")` |
| 4 | 被拖拽卡片归位动画 | 250ms `--yl-ease-out`，阴影消失 |

> **[已知问题]** 当前代码库在 `onDragEnd` 中显示了 `message.info("已切换为手动排序")`，但 Toast 应在拖拽完成 300ms 后再显示，避免与卡片归位动画同时发生造成视觉混乱。

### 7.5 拖拽与其他交互的冲突处理

| 场景 | 处理方式 |
|------|----------|
| 点击卡片内按钮（如"查看详情"） | `distance: 4px` 约束确保点击不触发拖拽 |
| 卡片内有链接 | 链接元素需设置 `onPointerDown={(e) => e.stopPropagation()}` |
| 移动端长按 | `PointerSensor` 已统一处理，4px 距离约束适用 |

## 10. 移动端手势

### 10.1 手势定义

演立方 V4.7 移动端（Mobile S / Mobile M 端口，`< 768px`）支持以下手势交互。

| 手势 | 动作 | 适用场景 | 反馈 |
|------|------|----------|------|
| **Tap**（点击） | 选中 / 打开 | 卡片、按钮、列表项 | 150ms 高亮反馈（`#F0EEFF` 背景闪烁） |
| **Long Press**（长按） | 打开上下文菜单 | 商机卡片、方案卡片 | 长按 500ms 后触发，触觉反馈（`navigator.vibrate(10)`）+ 弹出菜单 |
| **Swipe Left**（左滑） | 展开行内操作 | 商机列表项、消息列表项 | 滑动 40px 后露出操作按钮（置顶 / 删除），背景 `#F0F1F4` |
| **Swipe Right**（右滑） | 返回上一页 | 全站非首页 | 滑动 80px 触发返回，小于 80px 回弹 |
| **Pull Down**（下拉） | 刷新列表 | 方案发现、商机中心、跟进中心 | 下拉 60px 触发刷新，顶部出现 Spin + "下拉刷新" 文案 |

### 10.2 手势详细规范

#### Tap（点击）

```
手指按下 ──→ 150ms 高亮 ──→ 手指抬起 ──→ 执行操作

  ┌──────────────┐       ┌──────────────┐       ┌──────────────┐
  │  Card 内容    │  →    │  Card 内容    │  →    │  Card 内容    │
  │              │       │ #F0EEFF 背景  │       │              │
  │              │       │ (高亮 150ms)  │       │ (跳转/打开)   │
  └──────────────┘       └──────────────┘       └──────────────┘
```

- 点击区域不小于 44 × 44px（Apple HIG 最小触控目标）
- 高亮反馈使用 `active` 伪类，`background: #F0EEFF`

#### Long Press（长按）

```
手指按下 ──→ 500ms ──→ 触觉反馈 + 弹出上下文菜单

  ┌──────────────┐       ┌──────────────┐
  │  Card 内容    │  →    │  Card 内容    │  +  ┌──────────┐
  │              │       │ (轻微缩小     │     │ Context  │
  │              │       │  scale 0.98)  │     │ Menu     │
  └──────────────┘       └──────────────┘     └──────────┘
                                               ↑ 出现在手指位置
```

- 长按 500ms 触发，避免与 Tap 和 Swipe 冲突
- 触发瞬间轻微缩放 `scale(0.98)` + 触觉反馈
- 菜单出现在手指位置上方（同 [9. 右键菜单](#9-右键菜单) 视觉规范）

### 11.2 AI 流式输出 (Stream Fade-in)

AI 返回内容时，文本以流式方式逐段淡入显示。

| 属性 | 值 | Token |
|------|----|-------|
| 动画名 | `yl-fade-in` | — |
| Duration | 250ms / 段 | `--yl-duration-normal` |
| Easing | `cubic-bezier(0,0,0.2,1)` | `--yl-ease-out` |
| 效果 | `opacity: 0→1` + `translateY(4px→0)` | — |

```
流式输出过程:

  t=0ms     t=250ms        t=500ms        t=750ms
  ┌──────┐  ┌──────────┐   ┌──────────────┐  ┌──────────────────┐
  │  ░░  │  │ 根据您的  │   │ 根据您的需求  │  │ 根据您的需求，我  │
  │ (淡入)│  │ 需求     │   │ ，我          │  │ 推荐以下方案：    │
  │      │  │ (已稳定) │   │ (已稳定)      │  │ (已稳定)          │
  └──────┘  └──────────┘   └──────────────┘  └──────────────────┘
  ↑ 新段淡入    ↑ 250ms后     ↑ 下一段淡入     ↑ 持续累加
    opacity:0   完全显示       opacity:0→1
    →1          opacity:1
```

**规则**:
- 每个文本段（如一句话或一个词组）独立执行 `yl-fade-in`
- 段与段之间的淡入可以有轻微重叠（上一段未完全结束时下一段开始）
- 流式输出期间输入框保持可用但"发送"按钮替换为"停止生成"按钮

## 12. 动效红线

### 12.1 禁止事项

以下动画行为在演立方 V4.7 中**严格禁止**。

| 编号 | 禁止行为 | 原因 | 替代方案 |
|------|----------|------|----------|
| R-01 | **页面过渡使用 bounce/弹性曲线** | B2B 场景需要沉稳感，弹性动画显得轻浮 | 使用 `--yl-ease-out` 减速曲线 |
| R-02 | **Loading Spin 持续超过 2 秒而无骨架屏** | 用户对空白等待的容忍度不超过 2 秒 | 2 秒后切换为 Skeleton 骨架屏 |
| R-03 | **同时运行超过 3 个动画** | 视觉混乱，性能下降 | 队列执行或简化为单一动画 |
| R-04 | **动画时长超过 500ms（循环动画除外）** | 超过 500ms 让用户感到迟钝 | 使用 `--yl-duration-slower` 500ms 为上限 |
| R-05 | **使用 `linear` 缓动（循环旋转除外）** | 线性缓动不自然，缺乏物理感 | 使用 `--yl-ease-default` 或 `--yl-ease-out` |
| R-06 | **循环动画用于非加载场景** | 循环动画暗示"进行中"，误用会误导用户 | 仅 `yl-thinking-pulse` 和 `yl-skeleton-pulse` 可循环 |
| R-07 | **卡片入场交错延迟超过 500ms** | 第 10 张之后的卡片等待过久 | 交错延迟最多到第 10 张（50ms × 10 = 500ms） |
| R-08 | **忽略 `prefers-reduced-motion`** | 无障碍要求，部分用户对动画敏感 | 必须实现降级处理 |
| R-09 | **悬停动画使用 `transform: scale` 超过 1.05** | 过度缩放显得不稳定 | hover 缩放不超过 `scale(1.02)`，或使用 `translateY(-2px)` |
| R-10 | **弹窗/抽屉无过渡动画直接显示/消失** | 突兀出现会造成用户认知冲击 | Modal 350ms 淡入/淡出，Drawer 350ms 滑入/滑出 |

### 12.2 动画预算

单页面同一时刻的动画预算：

```
┌─ 动画预算规则 ──────────────────────────────────────┐
│                                                    │
│  最多 3 个同时进行的动画:                            │
│                                                    │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐           │
│  │ 动画 1   │ │ 动画 2   │ │ 动画 3   │           │
│  │ (入场)   │ │ (hover)  │ │ (加载)   │           │
│  └──────────┘ └──────────┘ └──────────┘           │
│                                                    │
│  超过 3 个时，优先级:                               │
│  1. 加载动画 (最高 — 用户在等待)                    │
│  2. 交互反馈动画 (hover/click)                      │
│  3. 入场动画 (可延迟或取消)                          │
│  4. 装饰性动画 (首先取消)                           │
│                                                    │
└────────────────────────────────────────────────────┘
```

### 12.3 `prefers-reduced-motion` 降级

用户在系统设置中开启「减少动态效果」时，必须降级所有非必要动画。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

**降级后的替代反馈**:

| 原动画 | 降级后替代方式 |
|--------|---------------|
| 卡片交错入场 | 直接显示，无延迟 |
| 页面淡入 | 直接显示 |
| AI 思考脉冲 | 替换为静态文字 "AI 正在思考..." |
| AI 流式淡入 | 文字直接显示，无淡入效果 |
| 拖拽阴影 | 仅显示 1px 边框高亮，无阴影变化 |
| Toast 出现 | 直接显示，无滑入动画 |

### 12.4 性能约束

| 约束项 | 阈值 | 说明 |
|--------|------|------|
| 动画帧率 | ≥ 60fps | 仅使用 `transform` 和 `opacity` 做动画，避免触发 layout/paint |
| 动画层数 | ≤ 3 层 | 同时使用 `will-change` 的元素不超过 3 个 |
| 骨架屏切换时机 | 数据到达后 100ms 内 | 避免骨架屏闪烁 |
| 防抖/节流 | 搜索 300ms / 滚动 16ms / 窗口缩放 100ms | 避免高频回调 |
